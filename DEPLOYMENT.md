# Production Deployment Manual: MK SMM Panel

This document outlines the standard production release workflow for deploying the **MK SMM Panel** high-availability, high-performance web platform.

---

## 🛠 Prerequisites

Before starting, ensure your host server has the following packages installed:
1. **Docker Engine** (v24.0 or greater) & **Docker Compose**
2. **Reverse Proxy / Ingress** (e.g., NGINX, HAProxy, or Traefik)
3. **SSL Certificate** (obtained via Let's Encrypt or your custom Authority)

## 🐳 Container Orchestration via Docker Compose

Using Docker Compose facilitates zero-downtime, self-healing deployments.

### 1. Build and Launch Services

```bash
docker compose up -d --build
```

This commands standard steps:
- Compiles standard React production static files inside the builder stage.
- Compiles the self-contained production backend `dist/server.cjs` via esbuild.
- Initializes a slim execution container mapping port `3000` to the host workspace.
- Mounts `/app/database_store.json` as a persistent volume to preserve ledger balances and order registrations across container restarts.

### 2. Verify Status

```bash
docker compose ps
docker compose logs -f --tail=100
```

## 🛡 Production Reverse Proxy (NGINX Setup)

Configure NGINX to terminate HTTPS, compress traffic using gzip, and forward requests directly to the SMM container on port `3000`.

```nginx
server {
    listen 80;
    server_name mksmm.com www.mksmm.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name mksmm.com www.mksmm.com;

    ssl_certificate /etc/letsencrypt/live/mksmm.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mksmm.com/privkey.pem;
    
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Gzip Compression Rules
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket Upgrade Headers
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## 🔒 Advanced Security Rules & Hardening

1. **XSS & Content Security Policy (CSP)**:
   Ensure your proxy or backend injects standard security headers:
   - `X-Frame-Options: SAMEORIGIN` (prevents clickjacking attacks)
   - `X-Content-Type-Options: nosniff` (mitigates MIME-sniffing exploits)
   - `Referrer-Policy: strict-origin-when-cross-origin`
   
2. **Rate Limiting Protection**:
   The Express server incorporates IP rate limits. Ensure NGINX has `real_ip` modules configured so sub-client IP addresses are not masked as `127.0.0.1`.

3. **Backup Matrix**:
   Integrate cron tasks to copy `/app/database_store.json` to encrypted cloud vault buckets (e.g. Google Cloud Storage or AWS S3) every 6 hours.

## 📈 Troubleshooting & Performance Optimization

- **Checking DB Health**: Inspect `database_store.json` size. Make sure there are write and read privileges for the script runner user.
- **Flushing Caching Layers**: Client files use cache-busting entry hashes generated by Vite. If static resources fail to invalidate, perform a cloud CDN flush.
- **Node.js Memory Threshold**: Keep a container limit of 1GB RAM. Ensure docker-compose properties have standard limitations set for low resources platforms.
